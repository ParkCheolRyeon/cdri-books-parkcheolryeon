# CDRI Books (ParkCheolryeon)

## 프로젝트 소개

이 프로젝트는 Kakao Book Search API를 기반으로 도서를 검색하고, 검색 결과를 다양한 방식으로 탐색할 수 있도록 만든 애플리케이션입니다.

기본 검색뿐 아니라 제목, 저자, 출판사를 기준으로 세부 검색이 가능하도록 구성했고, 검색 결과에서 원하는 도서를 찜해 별도의 찜 목록 페이지에서 다시 확인할 수 있습니다.

또한 검색 상태가 URL 쿼리(`query`, `page`, `target`)와 동기화되도록 설계해 새로고침이나 공유 상황에서도 현재 검색 맥락이 유지되도록 했습니다. 최근 검색어와 찜 목록은 `localStorage`에 저장해 사용 흐름이 자연스럽게 이어지도록 구성했습니다.

## 실행 방법 및 환경 설정

### 환경 준비

- Node.js 및 npm 설치
- 프로젝트 루트 경로에 `.env` 파일 생성

```env
VITE_KAKAO_REST_API_KEY=YOUR_KAKAO_REST_API_KEY
```

### 로컬 실행

```bash
npm install
npm run dev
```

### 빌드 및 프리뷰

```bash
npm run build
npm run preview
```

## 폴더 구조

```bash
src/
  api/          # Kakao API 호출, zod 응답 검증, 에러 매핑
  components/   # 검색 폼, 상세검색 팝업, 도서 리스트, 공통 UI
  hooks/        # 검색 쿼리, 찜, 최근 검색어 관련 상태 훅
  pages/        # 도서 검색 페이지, 찜 목록 페이지, 페이지네이션 로직
  queries/      # React Query 옵션(캐시, 재시도 정책)
  styles/       # 디자인 토큰, 반응형 브레이크포인트
  lib/          # 검색 파라미터, storage 유틸, 환경 변수 접근
  router/       # 라우팅 구성
tests/
  e2e/          # Playwright E2E 시나리오
```

## 사용한 라이브러리와 선택 이유

### `@tanstack/react-query`

서버 상태를 효율적으로 관리하기 위해 사용했습니다. 캐싱, 재시도, 로딩 상태 처리 등을 직접 구현하지 않고 일관된 방식으로 다룰 수 있어 검색 기능에 적합했습니다.

### `react-router-dom`

검색 페이지와 찜 페이지 간 이동을 구성하고, 쿼리스트링 기반으로 검색 상태를 유지하기 위해 사용했습니다. URL과 화면 상태를 자연스럽게 연결할 수 있다는 점이 장점이었습니다.

### `@emotion/react`, `@emotion/styled`

컴포넌트 단위에서 스타일을 유연하게 관리하기 위해 선택했습니다. 디자인 토큰과 함께 사용해 일관된 스타일 시스템을 구성할 수 있었습니다.

### `@radix-ui/react-accordion`, `@radix-ui/react-dialog`, `@radix-ui/react-select`, `@radix-ui/react-tabs`

접근성이 고려된 headless UI 컴포넌트를 활용하기 위해 사용했습니다. 기본 동작과 WAI-ARIA 구조를 안정적으로 가져가면서도, Emotion과 조합해 원하는 형태로 자유롭게 스타일링할 수 있었습니다.

### `framer-motion`

상세검색 팝업, 최근 검색어 목록 등 인터랙션이 들어가는 영역에 자연스러운 움직임을 더하기 위해 사용했습니다.

### `zod`

외부 API 응답을 런타임에서 검증하기 위해 적용했습니다. 예상하지 못한 응답 구조에도 방어적으로 대응할 수 있어 안정성을 높일 수 있었습니다.

### `vitest`, `playwright`

핵심 로직은 단위 테스트로, 실제 사용자 흐름은 E2E 테스트로 분리해 검증했습니다. 기능 단위와 시나리오 단위를 나눠 확인할 수 있어 테스트 신뢰성을 높이는 데 도움이 됐습니다.

## 주요 기능

### 검색 경험 개선

- 기본 검색과 상세 검색(제목 / 저자 / 출판사)을 모두 지원합니다.
- 검색 결과는 페이지네이션으로 구성해 많은 결과도 단계적으로 탐색할 수 있습니다.
- 찜 목록 역시 동일한 기준으로 페이지네이션을 적용해 검색 페이지와 사용 경험을 맞췄습니다.
- 찜 상태는 검색 페이지와 찜 페이지에서 동일하게 동기화되도록 처리했습니다.

### 상태 관리와 오류 대응

- React Query의 Suspense 기반으로 검색 데이터 로딩을 처리했습니다.
- API 에러는 `retryable`, `auth-config`, `quota` 등으로 분류해 상황에 따라 다르게 대응할 수 있도록 구성했습니다.
- 에러 바운더리에서는 재시도 버튼을 제공해 복구 가능한 오류에 대해 사용자가 다시 시도할 수 있도록 했습니다.

### 테스트 기반 검증

- 단위 테스트에서는 스토리지 유틸, 검색 파라미터 파싱, 에러 매핑 등 핵심 로직을 검증했습니다.
- E2E 테스트에서는 검색, 최근 검색어, 상세검색, 찜, 찜 페이지 이동까지 실제 사용자 흐름을 검증했습니다.
- Playwright 프로젝트를 단계적으로 분리해 시나리오 간 의존 관계를 보다 명확하게 관리했습니다.

## 테스트 실행 방법

### 단위 테스트

```bash
npm run test:unit
```

### E2E 테스트

```bash
npm run test:e2e
```

E2E 테스트 실행 시에는 Playwright 설정에서 테스트용 `VITE_KAKAO_REST_API_KEY`를 주입해 동작하도록 구성했습니다.
